# Type de tâche : feature

## analyse
- Besoin métier, utilisateurs, critères d'acceptation (explicites et implicites), impacts sur les flux existants.

## plan
- Découpage en tâches livrables, des données vers la présentation ; une tâche de tests par comportement nouveau.

## implement
- Implémentation normale, tâche par tâche, un commit par tâche ou groupe logique.

## test
- Tests du **nouveau comportement** : nominal, limites, erreurs, droits.

## review
- Qualité, bugs, sécurité. Vérifier que chaque critère d'acceptation est couvert.

## simplifier
- Réduire le diff.

## gates
- G1, puis G2.

## pr
- Mettre en avant l'apport fonctionnel et la façon de le tester.
